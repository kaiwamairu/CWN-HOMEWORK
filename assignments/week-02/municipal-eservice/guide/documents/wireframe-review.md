## 1. เอกสารและแบบที่อนุมัติ

- บันทึกการอนุมัติคลิปประชาชน/เจ้าหน้าที่ตามข้อความผู้ใช้ใน chat พร้อม hash ของไฟล์
- ปรับ design system, layout matrix, plan และคำแนะนำ T001/T017/T071 ให้ตรงกัน
- ไม่มี app-header; ข้อมูลบัญชีและ logout อยู่ในเมนูโปรไฟล์ เมนูจอกว้างเปิดขึ้น จอแคบเปิดลง
- คงกรอบวันที่แบบปฏิทิน ค่า design token และ greeting fade เดิม รวม translateY(12px)
- อนุญาตเฉพาะคลิปกล้องนิ่งที่เลือกแล้ว พร้อม pause/play, poster, reduced motion และ error fallback
- สื่อเดิมทุกไฟล์คง byte hash เดิม ไม่มีการ generate/transcode เพิ่มในรอบนี้

| ตำแหน่ง | สื่อที่ใช้ |
| --- | --- |
| เข้าสู่ระบบประชาชน | LOGIN-CITIZEN ชายมองโทรศัพท์ จอหันเข้าหาตัว |
| เข้าสู่ระบบเจ้าหน้าที่ | LOGIN-STAFF หญิงใช้คอมพิวเตอร์สำนักงาน |
| หน้าหลักประชาชนและลงทะเบียน | 1A เทศบาลชานเมืองไทยแบบไม่มีคน |
| ตรวจสอบเอกสาร public | 3A เจ้าหน้าที่หญิงตรวจเอกสาร |
| ประวัติที่เก็บไว้ | 2A ประชาชนเขียนแบบฟอร์ม ไม่ใช้ในหน้า login |

## 2. ผลตรวจ prototype

| ชุดตรวจ | จำนวน | ผล |
| --- | --- | --- |
| เส้นทางและ validation พื้นฐาน | 46 | ผ่าน |
| เส้นทางเพิ่มเติมและ regression | 39 | ผ่าน |
| 15 หน้า × 375/768/1280px | 45 renderings | ผ่าน |
| 15 หน้า × loading/empty/error/forbidden/not-found ที่ 1280px | 75 states | ผ่าน |
| สื่อ ตำแหน่ง ปุ่มเล่น/หยุด fade และ reduced-motion/error fallback | 29 | ผ่าน |
| เมนูโปรไฟล์มือถือ: bounds และขนาดปุ่ม | 2 | ผ่าน |

ตรวจ normal render ว่า route ถูกต้อง ไม่มีหน้าล้นแนวนอน ข้อความไทยอ่านได้
input/select/textarea มี label และปุ่มมีชื่อ ไม่มี app-header ที่หลงเหลือ
Reduced motion ตรวจด้วย controller จริงใน iframe โดยจำลองค่า matchMedia ไม่ใช่การเปลี่ยน setting ของ OS

### เส้นทางที่เดินตรวจ

- ประชาชน: เข้าสู่ระบบ/OTP/lock ตัวอย่าง ลงทะเบียน/consent เลือกบริการ ค่าธรรมเนียม แนบไฟล์ตัวอย่าง QR/ชำระจำลอง ติดตาม ยกเลิก และส่งแก้ไขกลับ
- เจ้าหน้าที่/หัวหน้า: ตัวกรองคิว รับเรื่อง เปิดข้อมูลพร้อมเหตุผล ตีกลับ ส่งต่อทะเบียน → โยธา → หัวหน้า อนุมัติ/ไม่อนุมัติ กลับไปผู้มีสิทธิ์ออกเอกสาร และ public verify แบบปิดบังตัวตน
- รายงาน/Audit: ช่วงเวลาและ KPI ตัวอย่าง export PDF/XLSX preview และตรวจข้อมูล CSV ตัวอย่าง โดยไม่สร้าง download ลงโฟลเดอร์ผู้ใช้ระหว่างตรวจ
- ผู้ดูแล: ค่าธรรมเนียม/validation เพิ่มและลบวันหยุดพร้อมยืนยัน เปลี่ยนบทบาทและตรวจผลหลัง login รอบถัดไป
- การแจ้งเตือน/โปรไฟล์: เปิดคำขอแล้วอ่านแล้ว จำนวน unread ลดและแยกผู้ใช้ arrow/Escape/focus return บัญชีอ่านอย่างเดียว และ logout ถูกแท็บ

ดูภาพตัวอย่างจริง 6 กรณี: mobile upload, mobile profile/notifications, desktop correction confirmation,
dashboard, head approvals และ admin services ภาพ capture ชั่วคราวใช้เพื่อทบทวนหน้าตาใน session นี้

## ขอบเขตที่ยังเป็นงานแอปจริง

การอนุมัติแบบและผลตรวจนี้ไม่ปิด T001–T078 และไม่ใช่ผล canonical 51 TC
ยังไม่มี backend, การยืนยันตัวตน/สิทธิ์ฝั่ง server, ฐานข้อมูลเข้ารหัส หรือ transaction จริง
การส่งแก้ไขแสดง flow/status เท่านั้น การบันทึกไฟล์ กำหนดเวลา และขยาย SLA ต้องทำตาม T035
PDF/XLSX เป็น preview; CSV เป็นข้อมูลตัวอย่าง ยังไม่ใช่ผล audit/runtime acceptance
ไม่ได้อ้างว่าเป็น WCAG audit เต็มรูปแบบหรือผลตรวจ performance/security ของแอปจริง
