CONTRACT · สัญญาที่ทุกเว็บต้องทำตาม

ใช้ stack อะไรก็ได้ แต่ ทุกข้อในไฟล์นี้ต้องตรง ไม่เช่นนั้น TEST-PLAN.md กลางใช้กับเว็บของกลุ่มไม่ได้ ข้อความที่ test จะ assert ตรงตัวอักษร (รวมช่องว่าง, เครื่องหมาย – ขีดกลาง en dash U+2013 ในคำว่า "1–5", "1–500" และค่า – ของทันกำหนด %) ถูกกำหนดในตาราง 5 (เป็นข้อกำหนดของ TA ⚠️A-38) ที่มา: ตัวเลข/กฎ = REQUIREMENTS · ชื่อ/รูปแบบ = ข้อกำหนดของ TA ⚠️A-38

0. หลักการ

ข้อหลักการ
1ทุกองค์ประกอบที่ test ใช้มี data-testid ตามตารางต่อไปนี้ (kebab-case) · ถ้ามีหลายรายการ (แถว) ใช้ data-testid ซ้ำได้ และ test จะกรองด้วยแอตทริบิวต์ data-* ที่ระบุ
2ข้อความบนจอเป็นภาษาไทยตามที่ระบุ · วันที่ 4 ธ.ค. 2569 16:30 · เงิน ฿1,010 (A-04)
3องค์ประกอบวันเวลาต้องมี data-iso="2026-12-04T16:30:00+07:00" ด้วย (A-51)
4สถานะ/ระดับมีทั้งข้อความไทยและ data-status / data-level เป็นรหัสอังกฤษ (ตาราง 4)
5ปุ่มที่ "ต้องไม่มี" ในบางสถานะ = ไม่ render ในหน้า (test ตรวจ count() == 0) ส่วนปุ่มที่ "ใช้ไม่ได้" = disabled
6API ตอบ JSON เป็นหลัก ข้อผิดพลาดรูปแบบ {"code":"...","message":"..."} (A-38) · ใช้ session cookie (HttpOnly) หลังล็อกอิน
7ทุกคำขอ HTTP ยกเว้น /api/test/* ต้องประเมินแจ้งเตือน SLA ตามนาฬิกาปัจจุบัน (A-30) และอัปเดตสถานะยกเลิกอัตโนมัติที่เลยเวลา (A-46)
8TEST_MODE=1 เปิด /api/test/* · ไม่ตั้ง → /api/test/* ตอบ 404 · BUG_MODE ดู BUGS.md
9POST /api/test/reset ล้าง session/cookie ของทุกคน รวมตัวนับ OTP ผิด การล็อก แจ้งเตือน audit และไฟล์ที่อัปโหลดใหม่ → ทุก TC ต้องล็อกอินใหม่หลัง reset ทุกครั้ง (cookie/request context เก่าใช้ไม่ได้)
10เซิร์ฟเวอร์ต้องรับ request body ได้อย่างน้อย 6 MB เพื่อให้ไฟล์ 5,242,881 ไบต์ได้ 400 FILE_TOO_LARGE พร้อมข้อความ ไฟล์ใหญ่เกิน 5 MB (ไม่ใช่ 413 จากเฟรมเวิร์ก) และไฟล์ 5,242,880 ไบต์พร้อมส่วนหัว multipart ไม่ถูกตัด
11ตัวแปร DB_PATH ชี้ไฟล์ฐานข้อมูล (ถ้าใช้ฐานข้อมูลไฟล์) เพื่อให้ TC-NFR-04 ตรวจแบบ inspection ได้
