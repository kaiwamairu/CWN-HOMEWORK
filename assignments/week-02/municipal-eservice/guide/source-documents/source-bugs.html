BUGS · BUG_MODE ไว้พิสูจน์ว่า test จับบั๊กได้จริง

เว็บของกลุ่มต้องรองรับตัวแปรสภาพแวดล้อม BUG_MODE เป็นรหัสบั๊กคั่นด้วยจุลภาค เช่น BUG_MODE=B03,B07 · ไม่ตั้ง (หรือว่าง) = เว็บถูกต้อง 100% ที่มา: DECISIONS ข้อ 15–16 · แนวคิดจาก LAB 13 ของผู้สอน (บั๊กที่ซ่อนอยู่ในเว็บที่ "ผ่านหมด") · ทำงานเมื่อ TEST_MODE=1 เท่านั้นก็ได้

ข้อกติกา

3เปิดหลายตัวพร้อมกันได้ (B03,B07) ผลคือการรวมกันของแต่ละตัว
4บั๊กต้องอยู่ที่ ตรรกะฝั่งเซิร์ฟเวอร์ (เช่น B07 ต้องเป็น API ไม่เช็กสิทธิ์ ไม่ใช่แค่ซ่อนปุ่ม)
5ห้ามแก้ TEST-PLAN ให้ผ่านตอนเปิดบั๊ก · ถ้า TC ที่ควรล้มกลับผ่าน แปลว่า test ผ่านหลอก (ดูข้อ 4)

3. วิธีพิสูจน์ว่า test จับบั๊กได้

ขั้นทำอะไรต้องเห็นอะไร
1รัน ชุดเต็ม 51 TC กับเว็บถูกต้อง: TEST_MODE=1 (ไม่ตั้ง BUG_MODE)ผ่านครบ 51/51 · ถ้าไม่ครบให้แก้เว็บ (หรือแก้ test ถ้าผิดที่ test) ก่อนไปขั้นต่อไป
2รันซ้ำอีกรอบทันที (ไม่ restart เว็บ)ผ่านครบ 51/51 อีกครั้ง (พิสูจน์ว่า reset ทำให้ผลซ้ำได้ ไม่ใช่ผ่านเพราะข้อมูลเหลือจากรอบก่อน)
3สำหรับ B01 ถึง B12 ทีละตัว: restart เว็บด้วย TEST_MODE=1 BUG_MODE=Bxx แล้วรัน ชุดเต็มชุด TC ที่ล้ม = คอลัมน์ "TC ที่ต้องล้ม" (ทุกตัวต้องล้ม) + อาจรวม "TC ที่อาจล้มด้วย" · TC อื่นทั้งหมดผ่าน
4ดูข้อความที่ล้มข้อความ assert ต้องบอกว่า ค่าจริงต่างจากค่าที่คาดหวังตรงไหน (เช่น expected ฿1,010 received ฿1,000) ไม่ใช่ล้มเพราะ timeout หรือหา element ไม่เจอ
5ลองรวม: BUG_MODE=B03,B07 และ BUG_MODE=B01,B05,B09ล้มเท่ากับ union ของแต่ละตัว (ไม่หายไป ไม่เพิ่มแปลก ๆ)
6ปิดบั๊กทั้งหมดอีกครั้งกลับมาผ่าน 51/51

คำสั่งตัวอย่าง (ปรับตาม stack ของกลุ่ม):

TEST_MODE=1 <start-web>                       # ไม่มี BUG_MODE
npx playwright test --reporter=list           # คาดหวัง 51 passed

TEST_MODE=1 BUG_MODE=B01 <start-web>
npx playwright test --reporter=list           # คาดหวัง TC-FEE-01 failed อย่างเดียว (ที่เหลือ passed)

5. Triage: ผลที่ได้ไม่ตรงที่คาด ทำอย่างไร

อาการแปลว่าต้องทำ
TC ที่ระบุล้ม และที่เหลือผ่านtest จับบั๊กได้ ตรงแผนบันทึก ✅
TC ที่ระบุ ผ่าน ทั้งที่เปิดบั๊กtest ผ่านหลอก หรือเว็บยังไม่ได้ใส่บั๊กจริงตรวจว่าเว็บใส่บั๊กตรงจุดตาม "เปิดแล้วผิดอย่างไร" (ยิง API ตรง ๆ ดูค่า) · ถ้าบั๊กถูกใส่แล้วแต่ test ยังผ่าน แก้ assert (มักเกิดจากอ่านผลจากหน้าจอแทนค่าที่คิดจากกฎ หรือยกเลิกการตรวจที่ขอบ)
TC อื่น (นอกตาราง 2) ล้มด้วยบั๊กรั่วเกินจุด หรือ test พึ่งกันเองตรวจว่า BUG_MODE กระทบเฉพาะจุด (กติกาข้อ 1–2) · ตรวจว่า TC ไม่ใช้ข้อมูลที่ TC ก่อนหน้าทิ้งไว้ (ต้อง RESET ต้นทุก TC)
เปิดบั๊กตัวไหนก็ล้มเยอะทั้งชุดparse BUG_MODE ผิด (เช่นช่องว่าง) หรือ reset ล้าง seed ไม่ครบพิมพ์ BUG_MODE ออกมาดูตอนเริ่มเว็บ · รันชุดเต็มโดยไม่ตั้ง BUG_MODE ให้ผ่านก่อน
ล้มด้วย timeout / หา element ไม่เจอ แทนที่จะเป็นค่าต่างtest เปราะ ไม่ได้จับบั๊กจริงแก้ให้รอสถานะที่แน่นอน (เช่นรอ payment-status = ชำระแล้ว) และตรวจค่าตามตาราง
เปิดแล้วล้มต่างวันกัน (flaky)race จริงหรือเวลาจริงรั่วตรวจว่ากฎเวลาอ่านจากนาฬิกาทดสอบ ไม่ใช่เวลาเครื่อง · B08 ต้องล้ม ทุกครั้ง เมื่อยิงพร้อมกัน ถ้าบางครั้งผ่านให้เพิ่มจำนวนการยิง (API 10 ครั้งพร้อมกัน)
รวมบั๊ก 2 ตัวแล้วผลไม่เท่า unionบั๊กสองตัวแก้ที่เดียวกันแยกจุดแก้ของแต่ละตัวให้อิสระต่อกัน
